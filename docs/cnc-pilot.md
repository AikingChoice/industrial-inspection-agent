# CNC 主轴状态监测试点

## 目标

在一条产线的一类 CNC 设备上，验证系统能否发现主轴温度、振动等状态异常，并为维修人员提供有证据来源的排查建议和工单草稿。首期是只读的维护辅助工具，不承担安全联锁、设备控制或自动维修决策。

## 试点边界

- 选择一台设备或同型号的小范围设备，先聚焦主轴轴承/温升相关的一类故障；按运行/停机状态分别标定阈值，避免把停机数据当成故障。
- 数据通过只读网关或已有 SCADA/MES 接口进入系统；禁止从该服务向 PLC/CNC 写入控制指令。
- 保留设备标识、带时区的采集时间、测点名称和值、单位、运行状态和加工任务标识。传感器值要能关联到测点定义和校准记录。
- 若测点在运行、待机、停机等状态下有不同基线，在阈值 profile 中分别配置 `by_state` 限值；状态缺失或没有对应配置时，停止自动诊断并转人工复核。
- 规则和信号处理负责异常检测；知识库和模型只用于整理维修手册、历史案例和诊断解释。
- 模型建议必须带引用证据和人工复核状态。低置信度、数据质量差或知识库无匹配时，明确返回“需人工判断”，不得编造维修结论。
- 工单先作为本地草稿。接入 CMMS 前，需由设备维护负责人审核字段、权限和重复工单处理规则。

## 数据验证阶段

1. 由设备工程师确认传感器位置、单位、采样周期、正常工况范围和已知故障模式。
2. 回放有代表性的历史数据，覆盖正常生产、换刀/启停、负载变化、已知异常、传感器掉线和坏值。
3. 同步保存检测输入、规则/模型版本、知识库文档版本、输出、人工结论和后续维修结果，形成可复盘样本。
4. 先在只读旁路模式运行；维护人员对照现有巡检和维修判断，评估误报、漏报及可操作性。

## 试点验收指标

上线前由工厂维护团队约定阈值，至少跟踪：

- 遥测数据完整率、时间戳延迟和无效值比例；
- 每台设备每班/每周误报数量及已知故障的检出情况；
- 预警提前量、维修人员采纳率和人工改写原因；
- 从预警到确认、维修关闭的链路是否可追溯；
- 服务不可用时数据是否可补传，恢复后是否产生重复告警/工单。

不要仅用模型置信度或合成模拟数据作为上线验收依据。要先使用现场数据和维护人员确认的故障结果建立基线。

## 上线前必须完成

- 生产网络分区、只读服务账号、密钥管理、网关/TLS 身份认证、访问审计和备份/恢复演练；
- 遥测持久化、去重、断连缓存、重放和告警抑制策略；
- 明确服务等级、值班责任、故障降级和人工接管流程；
- LLM/向量库超时、限流、模型不可用和不可信文档的安全处理；
- 对依赖、容器镜像、上传内容、权限和日志中的敏感数据进行部署评审。

本方案描述试点范围，不代表仓库当前代码已经具备上述全部能力。
